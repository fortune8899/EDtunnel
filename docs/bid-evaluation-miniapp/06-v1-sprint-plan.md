# V1 开发冲刺计划（第 2 阶段）

> 目标：把“可点击原型”推进到“可用 MVP（前后端联调 + 可导出）”。

## 1. 里程碑

### M1：基础工程搭建（2~3 天）
- 前端：uni-app/Taro 项目初始化，页面空壳（首页/记录/分析/我的）。
- 后端：NestJS 初始化，完成 JWT 鉴权与健康检查接口。
- 数据库：执行 `03-data-model.sql` 建表脚本。

### M2：核心业务闭环（4~6 天）
- 记录 CRUD：新增、编辑、删除、查询。
- 列表筛选：日期范围、专业、地点。
- 表单校验：按 `05-ui-copy-and-validation.md` 实施。

### M3：统计看板（3~4 天）
- 概览接口：日/周/月/年统计。
- 趋势接口：按粒度聚合评次与金额。
- 专业 TopN：按抽取次数排序。

### M4：导出与验收（2~3 天）
- CSV 导出接口。
- E2E 冒烟测试。
- 内测发布与问题修复。

## 2. 角色分工建议
- 产品：验收口径、字段定义、文案终审。
- 前端：表单页、列表页、看板页、登录态管理。
- 后端：鉴权、记录模块、统计模块、导出模块。
- 测试：接口回归、跨端兼容、导出结果核对。

## 3. 风险与对策
1. **字段频繁变更**：第 1 周锁定 V1 字段，变更走评审。
2. **统计口径不一致**：建立“口径字典”，接口返回包含计算说明。
3. **导出性能问题**：V1 先做同步小文件导出，大文件后续做异步。
4. **跨端样式偏差**：先保证微信小程序端，H5 次级适配。

## 4. 交付定义（DoD）
- 关键路径可用：新增记录 → 列表可见 → 看板统计更新 → 可导出 CSV。
- 所有必填字段与错误文案符合规范。
- 至少 20 条样本数据验证统计准确性。
